1接上手机，说出任务

  1. 连接：用可传数据的 USB 线连接 Mac 和 iPhone。
  2. 解锁：保持手机解锁和唤醒；如有系统信任提示，由你确认。
  3. 开始：在 Codex 聊天中发送下面这句话。

用 iPhone Use 连接我的手机，复用现有配置，检查可用后打开手机屏幕。

日常不需要重新安装。Codex 会检查并复用配置，必要时启动服务。新聊天会重新检查连接；看到 ready=true 表示手机通道可用。

这次修了什么：安装时的原版 0.3.12 已使用 USB，但底层 WDA 默认监听所有网络接口，可能额外暴露到局域网。本机修复版把手机端控制和屏幕流服务限制为回环地址，保留 USB 通道；不是从 Wi-Fi 控制改成 USB 控制。

Xcode 窗口可以关闭或退出。后台服务仍要运行；完整 Xcode 要保留安装。详见第 7 节。

2认识侧边栏画面

Codex 正在执行任务时，尽量不要同时点击。需要自己接手时，先说“暂停手机访问，我来操作”。

3用一句话说明任务

说清 哪个 App、做什么、范围、要什么结果。如只想读取，也明确说出来。

示例 A · 读取信息

整理节目收藏

打开小宇宙，整理我最近收藏的 5 期节目，列出标题和主播。只读取，不取消收藏；读不到的字段标为未获取。

示例 B · 查看设置

先解释，再决定

打开 iPhone 的通知设置，查看微信当前的通知选项，解释各项作用。先不修改设置。

示例 C · 写入内容

保存一条备忘录

在备忘录新建“周末采购”，内容为“牛奶、鸡蛋、咖啡豆”。完成后核对标题和内容，不改已有笔记。

通用模板 · 替换括号内容

给出清楚的边界

在【App】完成【任务】，范围是【日期或条数】。不要【限制】。最后给我【表格或结论】，并核对【关键字段】。

示例需对应 App 已安装，且目标页面可访问。列表过长或字段读不到时，应注明范围与缺项，不把部分结果当成完整结果。

4登录和 Face ID：按这张图接手

遇到 App 认证时，Codex 会暂停手机访问并清除预览画面。密码和验证码只在手机上输入。

原版与修复版：本人完成密码、验证码和 Face ID 是原版已有的规则。原版暂停预览时保留旧画面并加遮罩；本机修复版新增清除旧画面、在插件代码中阻断读取和操作，以及恢复前的 Mac 本人确认。这里的“原版”指安装时的 0.3.12。

1 · 手机
完成认证输入密码，或完成 Face ID。停留在目标页面。
2 · 聊天
回复“已完成继续”告诉 Codex 认证完成，等待 Mac 确认窗口。
3 · Mac
点“恢复手机访问”由你亲自点击。选择“保持暂停”则继续阻断。
4 · Codex
读取新页面并继续使用当前状态，不重复已完成的动作。
“已暂停”是保护状态。刷新按钮不能解除它。聊天中说“继续”会触发恢复流程，但不能代替 Mac 确认。

如果只是手机锁屏：亲自解锁后回复“已完成继续”。Codex 会检查连接，并解除对应的锁屏暂停；App 认证暂停仍需要上面的 Mac 确认。

暂停手机访问，我要自己登录。等我完成后，再请求恢复。

看到的情况你要做什么

手机锁屏 / 等待解锁亲自解锁手机并保持唤醒，然后回复“已完成继续”。

更新前保留修复。你目前用的是本地修复版。升级插件前，先让 Codex 核对两项 P0 修复是否保留。

6核对结果，再停止服务

■

先看结果是否符合要求

核对 App、日期、条数和关键内容。发送、提交等动作如果结果不确定，先查记录，不要直接重做。

本次任务结束。请停止本次 iPhone Use 服务，并确认已停止；不要删除 App 或手机数据。

确认停止后即可拔线。关闭侧边栏只是收起画面，不等于停止手机服务。

记住这条路线：接线 → 解锁 → 说任务 → 必要时本人认证 → 核对结果 → 停止服务。

7Xcode 可以关闭，后台服务要保留

使用这套插件启动服务后，可以关闭 Xcode 窗口，也可以退出 Xcode。插件用独立的后台 xcodebuild 进程运行手机服务，不依赖 Xcode 图形界面。

你要做的事是否影响使用
关闭窗口 / 退出 Xcode本插件启动的后台服务可以继续运行。
结束 xcodebuild 或 USB 转发会使手机通道停止，使用期间不要结束这些进程。
卸载 Xcode / Mac 睡眠 / 拔 USB会影响构建、启动或连接。保留完整 Xcode，使用时让 Mac 唤醒并接好 USB。
管理 Apple 账号、证书或设备需要时再打开 Xcode，按系统提示操作。

手动启动的例外：如果用 Xcode 的 Product → Test 启动 WDA，它由该测试会话管理。停止测试会停止其服务；先让 Codex 检查归属，再改用插件启动。

请确认 iPhone Use 是由插件后台任务启动，并检查 ready=true。确认后我会退出 Xcode 窗口，继续使用手机。

8升级前，先保留两项修复

安装新版不会自动保留本地修复。需要保留：① WDA 仅监听回环地址；② 认证暂停阻断、清屏和本人确认恢复。

1 · 保存
提交 + 回退点把修复保存在维护分支，建立 tag，并在仓库外另存备份。
2 · 合并
检查上游差异合并更新时保留修复和测试；WDA 版本变化时重新适配补丁。
3 · 测试
通过后才安装检查网络限制、暂停阻断和界面；运行代码改变时使用新版本号。
4 · 验收
重连 + 真机核对核对加载版本、网络监听和暂停恢复。本人确认仍由你完成。

没有更新，就保留现状。上游没有新提交、安装代码也一致时，不重装、不重建 WDA。仅更新使用手册也不需要重启手机服务。

不能只看 ready=true：还要核对 network_hardened=true、控制和屏幕流的 USB 回环端点，以及暂停和恢复行为。详细命令见 升级维护流程。

请按 UPGRADE.md 升级 iPhone Use：先保存维护分支和回退点，检查上游差异，保留两项 P0 修复及测试。测试通过后再安装，必要时提示我重连，并核对真机网络与暂停保护；没有更新就保留现状。

9有问题时，从备份恢复

先恢复到新目录，再检查和安装。不要把旧源码直接覆盖到正在使用或尚有未保存改动的目录。

1 · 找到备份
bundle / 源码包bundle 保存 Git 历史；源码压缩包保存文件快照。
2 · 新目录
克隆或解压核对提交、tag 和文件。保留当前工作，便于回退。
3 · 安装
复用已有配置运行安装脚本，使用你自己的设备、Team 与有效 WDA 构建。
4 · 复查
重连并验收核对版本、READY、回环监听和暂停保护，确认恢复完成。
