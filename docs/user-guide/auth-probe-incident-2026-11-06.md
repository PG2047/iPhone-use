# 已解锁但页面仍不可读：认证探测复盘

2026-11-06，本地版 0.3.1508 修复认证恢复时的元素探测超时。手机已解锁、服务可达，WDA 的 `/element` 查询仍可能在 Identity Binding 阶段停住。此时返回 `probe_unavailable` 和 `probe_stage=element`，不能据此说手机仍锁着。

## 原因与修复

存在性检查只需要知道目标元素是否存在，但原查询仍可能承担完整元素匹配的成本。`server/wda_auth.py` 在认证探测期间临时启用 `useFirstMatch=true`，与紧凑响应一起使用，并在 `finally` 中恢复原设置。

认证边界不变：仍检查目标 App、解锁状态、认证阻断控件、连续两次稳定观察，以及暂停 epoch。没有绕过认证、直接删除暂停文件、改变网络监听范围或要求用户在 Mac 上点击额外确认。WDA HTTP 和 MJPEG 仍限于回环接口。

## 这次做错了什么

把“无法取得认证证据”解释成“用户没有解锁”，导致反复要求解锁或重新连接 USB。驱动可达、手机解锁、认证探测通过、业务页面完整可读是四项不同事实。以后报告具体失败阶段，不能用一种通用提示覆盖它们。

服务健康时不要为页面解析故障重建、重签或重启手机。先保存错误阶段；认证恢复后取得新的 READY 和页面观察，再由业务脚本验证读取结果。不重放结果未知的动作。

## 验证与限制

- 540 项 Python 测试通过，其中包含 24 项认证测试和原生回环网络测试。
- 60 项前端测试通过；构建、打包检查及 `git diff --check` 通过。
- 首次沙箱测试遇到本地 socket 权限限制；具备所需权限后完整测试通过，未把权限失败当作测试通过。
- 实机探测返回 `auth_ui_cleared`，随后新 READY 能读取已登录目标 App。
- 源码与安装缓存相关文件哈希一致，本机安装版本为 0.3.1508。未为此重签或重启手机。

这些证据验证认证探测恢复，不代表采购完成。后续业务页面仍暴露旧坐标、紧凑商品行和结算文字解析问题，由 home-shopping 1.6.10–1.6.12 单独修复。费用、自然免邮、配送及购物车最终状态必须由业务层另行核验。
